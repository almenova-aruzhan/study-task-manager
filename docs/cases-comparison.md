# Сравнение моделей поставки по трём кейсам

| Критерий | (а) ИС документооборота в госоргане по тендеру | (б) Новый мобильный продукт стартапа | (в) Миграция монолита банка в облако |
|---|---|---|---|
| Неопределённость требований | Низкая/средняя: требования и условия тендера задают рамки | Высокая: гипотеза продукта ещё не проверена | Средняя: бизнес-требования относительно стабильны, технические риски высоки |
| Стоимость ошибки | Высокая: возможны нарушения условий контракта и приёмки | Средняя: ошибка даёт потери времени и бюджета, но позволяет быстро изменить гипотезу | Очень высокая: ошибка может повлиять на доступность и банковские данные |
| Регуляторика | Высокая | Низкая/средняя | Очень высокая |
| Зрелость заказчика | Высокая: формальные процедуры и согласования | Низкая/средняя: продуктовая гипотеза требует проверки | Высокая: у банка есть зрелые процессы и требования к эксплуатации |
| Распределённость команды | Может быть высокой, взаимодействие формализовано | Часто высокая, требуется постоянная коммуникация | Может быть высокой, участвуют несколько технических и бизнес-команд |
| Тип контракта | Фиксированный тендерный контракт | Продуктовая разработка без фиксированного конечного объёма | Обычно внутренний/согласованный контракт с жёсткими требованиями к результату |
| Модель поставки | Predictive / Waterfall | Adaptive / Agile | Hybrid |
| Ритм принятия решений | По этапам и контрольным точкам | Короткие итерации и проверка гипотез | Этапы миграции + итеративная техническая работа |
| Переменная величина | Срок и объём ограничены контрактом; качество фиксируется приёмкой | Объём и содержание продукта меняются по результатам проверки гипотез | Объём и способ реализации могут уточняться, качество и безопасность не снижаются |
